jci-audit has no configuration file of its own — it reads the same `deny.toml` you'd hand
`cargo-deny` directly, and treats it as the single source of truth for both advisory ignores and
license policy. This guide covers only the subset of `deny.toml`/`about.toml` fields jci-audit
itself reads, writes, or derives from — not a full reference for either file. For every other
field, see [cargo-deny's](https://embarkstudios.github.io/cargo-deny/) and
[cargo-about's](https://embarkstudios.github.io/cargo-about/) own documentation.

---

## `deny.toml`

`jci-audit init` scaffolds this template:

```toml
[advisories]
db-path = "~/.cargo/advisory-db"
db-urls = ["https://github.com/rustsec/advisory-db"]
# Vulnerabilities are always denied by cargo-deny. unmaintained/unsound are
# scope selectors ("all" | "workspace" | "transitive" | "none"); "all" checks
# every crate in the graph and reports them as warnings.
unmaintained = "all"
yanked = "warn"
# Canonical source of truth for advisory ignores. `.cargo/audit.toml` is
# derived from this list via `jci-audit sync`. Give each entry a written
# justification.
ignore = []

[licenses]
# All licenses are denied unless explicitly allowed. Permissive licenses are
# allowed globally; weak-copyleft licenses are NOT — scope them to the specific
# transitive crates that carry them via [[licenses.exceptions]], so a new
# copyleft dependency fails the check until consciously reviewed.
allow = [
    "MIT",
    "Apache-2.0",
    "Apache-2.0 WITH LLVM-exception",
    "BSD-2-Clause",
    "BSD-3-Clause",
    "ISC",
    "Unicode-3.0",
    "Zlib",
    "BSL-1.0",
    "CDLA-Permissive-2.0",
]

# Example: admit a weak-copyleft license only for the crate that carries it.
# [[licenses.exceptions]]
# name = "some-crate"
# allow = ["MPL-2.0"]

[bans]
multiple-versions = "warn"
wildcards = "allow"

[sources]
unknown-registry = "warn"
unknown-git = "warn"
allow-registry = ["https://github.com/rust-lang/crates.io-index"]
```

This is the exact template `jci-audit init` writes to a new file. Run on an existing `deny.toml`,
`init` adds only the keys from it that are missing and changes nothing you already set. The
`allow` list is a deliberate permissive
baseline, not an arbitrary or expanded one; the same "consciously reviewed" friction the comment
describes for copyleft exceptions is the design intent for the whole file, not just that one list.

### `[advisories]`

| Key | Meaning |
|-----|---------|
| `db-path` / `db-urls` | Where `cargo-deny` clones/refreshes its advisory-db copy. `jci-audit release-prep` overrides `db-path` internally to pin the checkout for reproducibility — leave these at their defaults. |
| `unmaintained` | Scope selector (`"all"` \| `"workspace"` \| `"transitive"` \| `"none"`) for reporting unmaintained crates. |
| `yanked` | `"warn"` or `"deny"` for yanked crate versions. |
| `ignore` | The canonical list of accepted advisory IDs, each ideally with a comment explaining why. `jci-audit sync` derives `.cargo/audit.toml`'s `[advisories].ignore` from this — never edit `.cargo/audit.toml` directly. |

### `[licenses]`

| Key | Meaning |
|-----|---------|
| `allow` | The workspace-wide license allow-list. Every dependency's SPDX expression must resolve against this (or an exception) or `cargo deny check licenses` fails. |
| `[[licenses.exceptions]]` | Admits a license only for a named crate — the mechanism for weak-copyleft licenses (e.g. `MPL-2.0`) you don't want to allow globally. A new copyleft dependency without an exception fails the check until consciously reviewed. |

`jci-audit sync` also derives every `crates/*/about.toml`'s `accepted` list from this section — see
[about.toml](#about-toml) below.

### `[bans]` / `[sources]`

Standard `cargo-deny` policy, passed straight through to `cargo deny check bans sources` —
jci-audit doesn't interpret these itself. See
[cargo-deny's own documentation](https://embarkstudios.github.io/cargo-deny/) for the full field
reference.

## `.cargo/audit.toml` — derived, never hand-edit

```toml
# DERIVED FILE — do not edit by hand.
[advisories]
ignore = []
```

Regenerated by `jci-audit sync` from `deny.toml [advisories].ignore`, so `cargo audit` (run on its
own, without `cargo-deny`) honours the same ignore set. A hand-edit here is silently overwritten
the next time `sync` runs, and caught as drift by `sync --check` in the meantime.

## `about.toml`

If your crate ships `THIRD-PARTY-LICENSES.md` notices via
[`cargo-about`](https://github.com/EmbarkStudios/cargo-about), `jci-audit sync` also derives each
crate's `about.toml` `accepted` list — scoped to that crate's own dependency graph, not a copy of
`deny.toml`'s full workspace allow-list (SPDX expression evaluation against the allow-list,
reachability excluding dev-only edges). **A crate with no `about.toml` isn't required to have
one**: `sync` only looks for an existing `about.toml` and derives into it if found — a crate that
hasn't opted in to cargo-about notices is simply never touched.

**Discovery reads the workspace's own declared membership** — `cargo metadata`'s
`packages[].manifest_path`, i.e. `[workspace].members` in the root `Cargo.toml` — not a hardcoded
assumption that every crate lives under `crates/*/`. A workspace laid out any other way (a
root-level crate, `packages/*`, `libs/*`) is discovered correctly as long as it's a declared
workspace member.

```toml
# Derived — jci-audit sync manages this key:
accepted = [
    "Apache-2.0",
    "MIT",
    # ... only the licenses THIS crate's dependency graph actually carries
]

# Hand-authored — untouched by sync:
ignore-dev-dependencies = true

# A per-crate exception, mirroring deny.toml's [[licenses.exceptions]] — only
# written here if the exception's crate is reachable from THIS crate:
[option-ext]
accepted = ["MPL-2.0"]

# Hand-authored attribution pins for crates whose license needs disambiguating
# — never touched by sync:
[libgit2-sys.clarify]
license = "MIT"
[[libgit2-sys.clarify.files]]
path = "LICENSE-MIT"
checksum = "..."
```

Only the top-level `accepted` array and each qualifying exception crate's `accepted` key are
managed by `sync`. Everything else — comments, `ignore-dev-dependencies`, `.clarify` blocks — is
yours; `sync` merges rather than rewrites, so hand-authored content survives every run.

In a multi-crate workspace, each `crates/*/about.toml` gets its own derived list, scoped to that
crate's own reachable dependencies — not the workspace's full policy copied into every crate.
